PART 2: BUG ENCOUNTERED AND FIX
=========================================================

WHAT HAPPENED
-------------
After adding the profile picture / avatar feature to the top-right corner
of the dashboard, clicking "Continue to HealthLens" from the Guide screen
crashed with:

    javafx.fxml.LoadException:
    /HealthLens/target/classes/com/healthlens/HealthLens.fxml:60

    Caused by: java.lang.UnsupportedOperationException:
    Cannot determine type for property.

This meant the FXML file failed to load at all, so the user could never
reach the main dashboard once the profile avatar was added.

ROOT CAUSE
----------
The profile avatar was built from a StackPane containing a Circle, a
Label, and an ImageView layered on top of each other. A <tooltip> element
was attached directly to that StackPane in the FXML:

    <StackPane fx:id="profileAvatarStack" ...>
        <Circle .../>
        <Label .../>
        <ImageView .../>
        <tooltip>
            <Tooltip text="..." />
        </tooltip>
    </StackPane>

The problem: <tooltip> is only a valid FXML property on subclasses of
javafx.scene.control.Control (Button, Label, Slider, etc.), because only
Control has a setTooltip() method. StackPane is a plain layout container
(javafx.scene.layout.Pane), NOT a Control, so it has no tooltip property
at all. When the FXMLLoader tried to look up a setter method for
"tooltip" on StackPane, it found none, threw
UnsupportedOperationException, and the whole file failed to load.

THE FIX
-------
1. Removed the <tooltip> block from the StackPane in HealthLens.fxml.
2. Attached the tooltip in Java code instead, using Tooltip.install(),
   which works on ANY Node (not just Controls):

       Tooltip.install(profileAvatarStack,
           new Tooltip("Your profile — click to change picture, email, or background"));

   This line was placed once in the controller's initialize() method
   (not inside the method that also runs on every login, to avoid
   attaching the same tooltip twice).

VERIFICATION
------------
After the fix, every other <tooltip> use in the project was checked and
confirmed to be attached only to real Controls (Button, Slider) — this
was the only place the mistake had been made.


LESSON FOR FUTURE FXML WORK
=========================================================
Not every JavaFX node type supports every FXML property "shortcut" tag.
<tooltip>, <contextMenu>, <onAction>, etc. only work on the specific
class hierarchy that actually defines that property (Control and its
subclasses, in most of these cases). Plain layout containers — Pane,
StackPane, HBox, VBox, BorderPane, GridPane — do NOT support these
shortcuts, even though visually it can seem reasonable to want them
there. When in doubt, either wrap the content in a real Control, or set
the property in the Controller's Java code, as done here.
